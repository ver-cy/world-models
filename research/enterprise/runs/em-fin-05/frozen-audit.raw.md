# EM-FIN-05 — Frozen Semantic Audit (single independent run)

## Verdict

**REJECT as a normative set. Adjudicated HOLD as a reviewable draft.** No freeze.

The dossier's substantive boundary work is largely sound — the six-fact separation (quoted price / invoice amount / recognized cost / usage / allocated cost / valuation) survives audit, as does reuse of WM-FLW-015 for usage and WM-MAT-008 + Metric Definition for unit-cost observations. It fails as a normative set on four counts: three divergent invariant sets plus a fourth in the candidate record; a schema that cannot represent a residual at all; the absence of any period field on the run; and fixtures that are prose assertions over three mutually inconsistent, arithmetically broken scenarios.

### Adjudication of the central provider divergence — exact

**Held shape: one cluster candidate with internal addressable identities.** Specifically:

- **One** identifier-unassigned model/catalogue candidate, `Cost Allocation`, `modelId: null`, `registryId: null`, `allocationState: "unassigned"`.
- **Four** object-level stable identities inside it: `CostAllocationRule` (`allocationRuleId`), `CostAllocationRuleRevision` (`allocationRuleId` + `revision`), `CostAllocationRun` (`allocationRunId`), `CostAllocationResult` (`allocationRunId` + `resultId`).
- **Citation root = Run.** Derived Cost Records, audit trails and unit-cost observations cite `allocationRunId`, and a result line by the composite `(allocationRunId, resultId)`.
- **Rule is cluster-owned but not run-contained.** A run pins one immutable revision *by reference*; one revision is reusable across many runs; the rule's lifecycle is independent of any execution.
- **Results are run-contained *and* externally addressable.** Containment is a composite-key statement, not an addressability restriction.

**Three separate identifier-unassigned model candidates are rejected.** Rule, Run and Result fail the independent-model test jointly: single mastership authority (cost-governance/finance-analytics) across all three; no demonstrated reuse of Run or Result by any consumer outside the cluster; `Result` has no lifecycle, no invariants and no meaning independent of its Run; `Run` has no interpretable content without a pinned Rule revision. Grok's only load-bearing argument for separation — that Rule is authored, approved, effective-dated and retired independently of execution, and is reusable across runs — is fully satisfied *inside* one cluster by object-level identity plus reference-by-revision. Independent authoring lifecycle justifies an **independent object identity**, not an independent **model entry**.

**Grok's stated blocker is a category error and is rejected as stated.** "An identifier-unassigned aggregate cannot be cited by Cost Records" conflates two different identifier planes:

| | Model / catalogue identifier | Object-level stable identifier |
|---|---|---|
| Names | a specification/model entry | an instance governed by that model |
| Namespace | registry (`WM-…`/`EM-…`) | the model's own identity scheme (`allocationRunId`) |
| Allocated by | registry governance, one time | the owning authority, per instance, at execution |
| Cardinality | one per model | unbounded |
| Cited by | relation rows, crosswalks, profiles | derived facts, audit, reports, metrics |
| Present here | **absent by design** (`null`, pending) | **fully specified** in the candidate's `objects` block |

A derived Cost Record cites `(allocationRunId, resultId)`. That key is minted by the owning authority under the model's declared identity scheme and does not depend on the registry having allocated a model identifier. Registry non-allocation blocks **publication, relation rows and installability** — all already held — not instance citation. Conversely, a model identifier is never a substitute for an instance key: three model identifiers would still leave Grok's citation requirement unmet, because nothing cites a model entry per-execution.

Grok's position is additionally self-inconsistent and cannot be adopted verbatim: it demands "separate model identifiers" for Rule/Run/Result, then specifies "one Cost Allocation aggregate, root = Run", then closes "No model identifiers are assigned here." Its *substantive* requirements — Run as citation root, Rule referenced-by-version and not exclusively owned, result lines individually addressable, no second observation master, no implicit tag — are **accepted and carried into the held shape**. Its identifier-plane claim is **rejected**.

Claude's shape is rejected in two places: it mints `UnitCostObservation` as a new identity (breaches the WM-MAT-008 + Metric Definition reuse guard) and mints `CommitmentInstrument` (breaches the no-identifier-for-missing-binding guard). Local's shape is accepted as the base, corrected per the defects below.

**No allocation approval is inferred or conferred.** No rule in this dossier is approved; no run is authorized; this audit approves nothing.

## Material defects

### Identity and mastership

**1. The model/object identifier planes are nowhere distinguished in the artefacts, so the divergence is unresolvable by a reader.**
Evidence: `allocationState: "unassigned"` sits in the same record as `objects.*.identity: ["allocationRunId"]`, with no statement of what plane each occupies; Grok's blocker follows directly from the omission.
Remediation: add to the candidate record, as a sibling of `identityTest`:
`"identifierPlanes": {"modelIdentifier": {"plane":"registry-catalogue","value":null,"state":"unassigned","citedBy":["relation-rows","crosswalks","profiles"],"blocks":["publication","relation-assertion","installability"]}, "objectIdentifiers": {"plane":"instance","mintedBy":"owning authority under the declared identity scheme","independentOfModelAllocation":true,"citedBy":["derived cost records","audit","reports","unit-cost observations"]}}`
and the invariant: *"A model identifier is never substituted for an object identifier, and object-level citation does not depend on registry allocation."*

**2. No declared citation contract for derived facts; `CostRecord` is used normatively in all three studies and modelled nowhere.**
Evidence: Local ("typed, run-scoped Cost Records"), Claude (`CostRecord` with mandatory `cost_basis`), Grok ("Cost Records are typed and derived; they cite a Result") — absent from `objects`, yet invariant 1 ("every cost assertion declares basis, period and currency") binds it.
Remediation: either add `CostRecord` to `objects` with `identity: ["costRecordId"]`, `required: ["costBasis","period","currency","amount","citedRunRef","citedResultRef","sourceMasterRefs"]`, or delete every normative use of the term and restate invariant 1 over named modelled objects. Do not leave it half-modelled.

**3. `AllocationResult.required.targetRef` makes a residual unrepresentable — a hard contradiction with the conservation invariant.**
Evidence: invariants require residual to be *materialized as a result*; a residual has no allocation target; `targetRef` is unconditionally required.
Remediation: add `residualKind` to the object with the closed enum `["untagged-base","unmapped-target","unused-reserved-capacity","rounding-remainder","held-discount","base-incompleteness"]`; make `targetRef` required **iff** `residualKind` is absent and forbidden when present; add Grok's `isResidual` as derived (`residualKind != null`), not stored.

**4. `UnitCostObservation` has no owning plane.**
Evidence: the candidate `excludes` metric-definition identity and lists WM-MAT-008 only as a reference; the profile merely *constrains* unit-cost observations; Claude mints it as a new identity. No artefact states who masters the observation act.
Remediation: declare it in the profile, not the model: `"profiledObjects": {"UnitCostObservation": {"observationAct":"WM-MAT-008","ratioDefinition":"EM-DAT-05 Metric Definition (unassigned)","denominatorQuantity":"WM-FLW-015","newIdentity": false}}`, and strike Claude's "new derived-metric identity".

**5. Reserved-capacity instrument mastership is left unresolved, with two incompatible dispositions in one dossier.**
Evidence: Local — reuse contract/commitment authorities, "do not allocate another identifier merely because the dossier lacks their binding"; Claude — `CommitmentInstrument` **new**, in the minimal completion shape.
Remediation: adopt Local. Strike `CommitmentInstrument` from the completion shape; add the hold *"Commitment-instrument mastership is unbound; no candidate may be raised until the commercial-contract authority is identified"*; represent commitment effects only as typed `sourceAmountDerivation` components with a `commitmentRef` whose target master is `null` + held.

**6. `WM-ECO-012` is referenced by both the candidate and the profile and is discussed in none of the three studies, under a purpose string that conflates two different things.**
Evidence: `{"target":"WM-ECO-012","purpose":"Budget or commitment context…"}`. A budget authority is not a commercial-commitment authority.
Remediation: delete the row, or split it and cite the evidence that establishes each. Unevidenced reference rows may not survive into a frozen set.

**7. A reference row is asserted to a base with no approved outgoing relations.**
Evidence: Local hold — "WM-ECO-002 has no approved outgoing relations"; Claude — "a WM-ECO-002 edge cannot be relied on"; yet `boundary.references` carries a WM-ECO-002 row with no held marker.
Remediation: add `"assertable": false, "heldOn": "no approved outgoing relations on WM-ECO-002"` to that row, and the same treatment to WM-MAT-008 pending its `boundary-review-required` resolution and the registry-plane/subject-kind mismatch Claude records. A reference you cannot assert must be marked, not listed silently.

### Lifecycle

**8. `identityTest.independentLifecycle` fuses two incompatible state machines into one array.**
Evidence: `["draft","approved","effective","executed","superseded","retired"]` — `draft→approved→effective→retired` is the Rule; `executed→superseded` is the Run. No object has this lifecycle.
Remediation: replace with `"lifecycles": {"CostAllocationRule": ["draft","approved","effective","superseded","retired"], "CostAllocationRuleRevision": ["draft","approved","effective","superseded"], "CostAllocationRun": ["executing","closed","reconciled","superseded"], "CostAllocationResult": ["immutable"]}`.

**9. `CostAllocationRule.lifecycle` contains `"suspended"`, which appears in no study and has no defined effect.**
Remediation: either define it mechanically — *"suspension blocks new runs pinning any revision of this rule; in-flight runs complete; historical runs and results remain valid and resolvable"* — or delete the state.

**10. Run is declared immutable yet carries a forward `successorRunRef` that can only be written after close.**
Remediation: delete `successorRunRef` from `CostAllocationRun`. Record linkage on the successor: `required: ["supersedesRunRef","correctionReason"]` when the run is a correction, with `correctionReason` drawn from the closed enum `["restated-usage","corrected-invoice","credit-note","rule-defect","base-completeness-fix","target-remapping"]`. Any predecessor→successor index is a derived view, never run content.

**11. `CostAllocationRule.required.currentRevisionRef` is a stored mutable pointer that contradicts effective-dating, and no invariant forbids overlapping revision intervals.**
Remediation: delete `currentRevisionRef`; resolve revisions by as-of date against `effectiveFrom`/`effectiveTo`. Add the invariant *"Effective intervals of revisions of one rule are pairwise non-overlapping and gapless-or-explicitly-gapped"* and a machine check over the interval set.

**12. Result lifecycle is unstated, and Claude's formulation contradicts predecessor preservation.**
Evidence: `AllocationResult` has no lifecycle field; Claude — "immutable, lives and dies with its run."
Remediation: state *"Results are immutable and remain resolvable after their run is superseded; supersession is not deletion."* Dying with the run would void metric-vintage preservation.

**13. Axis may silently change across revisions of one rule.**
Evidence: `axis` sits on `CostAllocationRule.required`, but revisions are the immutable unit and nothing forbids a revision changing it; conservation and non-additivity are run-scoped and inherit axis through the pin.
Remediation: declare `axis` identity-fixing: *"A revision may not change the axis; an axis change requires a new rule identity."*

### Conservation, residual, multi-axis

**14. `sourceAmount` has no basis discriminator, so the conservation equation is ambiguous between gross, invoice-net, amortized-effective and recognized.**
Evidence: Grok makes discount timing a rule attribute with two legal outcomes (reduce source before allocation / carry discount as its own residual) — these produce *different source amounts for the same invoice*, and the schema cannot tell them apart.
Remediation: add to `CostAllocationRun.required`: `sourceAmountBasis` ∈ `["gross-listed","invoice-net","amortized-effective","accrued-unbilled","recognized"]` and `sourceAmountDerivation` as a required ordered component list `[{componentKind, amount, sourceMasterRef}]` that must sum to `sourceAmount`.

**15. `weight` is required on every result, which makes Σ weights ≤ 1 undecidable once residual is materialized.**
Evidence: if residuals carry weights, Σ = 1 exactly; if not, Σ ≤ 1. Both readings are in the dossier.
Remediation: define `weight` as share-of-**allocable-base**, present only on target results; residual results carry `residualShare` (share of source). Restate as: *"Σ(targetWeights) = 1 ± weightTolerance over the allocable base, and Σ(targetAmounts) + Σ(residualAmounts) = sourceAmount ± amountTolerance."* Two tolerances, separately declared.

**16. `tolerance` is a single scalar with no unit, no kind, and no stated absorber of the rounding remainder.**
Remediation: replace with `"tolerance": {"amountTolerance": {"value": …, "unit":"minor-currency-units"}, "weightTolerance": {"value": …, "unit":"ratio"}}`; add `roundingPolicy.remainderAbsorption` ∈ `["largest-remainder-to-targets","residual-rounding-remainder"]`; add the invariant *"A rounding remainder is materialized, never discarded."*

**17. Non-additivity is undecidable because "the same source" is never defined.**
Evidence: all three studies forbid summing parallel-axis runs "over the same source"; two runs may cite overlapping-but-unequal `sourceRecordRefs`.
Remediation: define source identity as the digest of the canonical-ordered `sourceRecordRefs` ∪ `sourceAmountBasis` ∪ `sourcePeriod` ∪ `currency`, stored as `sourceDigest`; trigger the non-additivity rejection on **non-empty intersection** of `sourceRecordRefs`, not on digest equality. Equality-only triggering is trivially evaded.

**18. Chained allocation is permitted implicitly and governed nowhere.**
Evidence: Local routes unused capacity "to a declared shared pool, allocated by its own rule" — a second run whose source is a prior run's result. No `upstreamRunRef`, no acyclicity rule, no cross-chain double-count prohibition.
Remediation: add `CostAllocationRun.optional: upstreamRunRef, upstreamResultRefs`; add invariants *"A chained run's source amount equals the cited upstream result amounts exactly"* and *"The run-chain graph is acyclic; a result may be the source of at most one non-superseded downstream run."*

**19. Claude's unused-capacity treatment is internally contradictory.**
Evidence: same paragraph offers "spread" as a treatment and then forbids being "silently absorbed into consumers' unit cost" — spreading *is* absorption into consumers.
Remediation: closed treatment enum `["shared-pool-result","separate-chained-run","residual-unused-capacity"]`. "Spread across consumers" is removed. Grok's "waste result on the commitment" and Local's "shared pool" both map into this enum.

**20. The shared pool is an allocation target with no master, while the candidate excludes target identity.**
Remediation: add a reference row for the responsibility/pool target authority, or declare the pool a `residualKind: "unused-reserved-capacity"` result with no target. Do not let an unmastered target enter a conserved result set.

**21. `reconciliation` is required but unstructured, and a within-tolerance variance has no recording obligation.**
Evidence: Claude requires three independent ties "recorded with variance and reason rather than forced to zero"; the schema has one opaque field.
Remediation: `"reconciliation": [{"tieKind": …, "expected": …, "actual": …, "variance": …, "varianceReason": …}]` with `tieKind` ∈ `["source-total","ledger-recognized-period","base-population-completeness"]`, all three required; add *"A non-zero variance within tolerance is recorded, not suppressed."*

**22. The no-implicit-tag rule is in Grok's set only.**
Evidence: Grok invariant 10; absent from Local, Claude and the candidate record. Without it, an "Unassigned" default target silently eliminates residual and satisfies conservation while destroying the residual signal.
Remediation: carry it into the normative set as a first-class invariant with a negative fixture.

### Currency and time

**23. `CostAllocationRun` has no period field at all, while invariant 1 requires period on every cost assertion.**
Remediation: add `CostAllocationRun.required: sourcePeriod` as a closed date-only interval `{from, to, calendarAuthority}`; add `usageIntervalRefs`; add the invariant *"A date-only period is never widened to an instant, and run execution time is never substituted for the source period."* Claude states this in prose; it is in no invariant set.

**24. Translation is mandated by invariant 10 and has no representation; results carry `amount` with no currency.**
Remediation: results inherit run currency (state it). Add a derived `TranslatedResult` with `required: ["sourceResultRef","amount","currency","rate","rateType","rateDate","rateSourceAuthority"]`, plus *"A translated result is never an input to conservation or to a unit-cost numerator."*

**25. Multi-currency sources are handled three incompatible ways.**
Evidence: Grok — "cross-currency lines are out of scope until a conversion rule exists"; Local/Claude — translate results after allocation, silent on multi-currency sources.
Remediation: adopt: *"A run has exactly one currency. A multi-currency source is sliced into one run per currency, each conserving independently; a cross-currency total is a translated presentation, never a run."* Add explicit run cardinality invariants: `|axis| = 1`, `|currency| = 1`. Local's invariant 4 only *scopes* the equation to one axis and currency — it does not forbid a two-axis run.

### Discount, unit economics, approval

**26. Discount treatment has three different option sets and no normative one.**
Evidence: Local — allowance identity retained, attribution basis added; Claude — follow-line / spread-on-base / shared-pool; Grok — reduce-source-before-allocation / discount-as-own-residual.

Silent netting is rejected under all four treatments.

**27. The unit-cost denominator's master is contested.**
Evidence: Claude — "functional unit taken from WM-FLW-015's normalizing variable"; Grok — "denominator is usage from WM-FLW-015", observation profiles WM-MAT-008; Local — "WM-MAT-008 plus Metric Definition". The candidate's WM-MAT-008 purpose string, *"Measured quantities and unit-cost observations"*, collapses the measurement act and the ratio definition into one row.
Remediation: three separate required bindings on the observation: `denominatorQuantityRef` → WM-FLW-015; `observationActRef` → WM-MAT-008; `metricDefinitionRef` + `metricDefinitionVersion` → EM-DAT-05 Metric Definition. Exactly one denominator source per observation. Split the WM-MAT-008 purpose row accordingly.

**28. `EM-DAT-05 Metric Definition` is load-bearing in invariant 14 and appears in neither the candidate's `references` nor the profile's `bases`.**
Remediation: add it to both, marked `allocationState: "unassigned"` and held.

**29. Denominator population completeness is not required, though base completeness is.**
Evidence: `baseCompleteness` is required on the run; the unit-cost denominator has no equivalent, so a biased denominator passes every check.
Remediation: add `denominatorCompleteness` to the observation with the same enum and coverage ratio as `baseCompleteness`.

**30. The residual share is declared on unit cost but has no stated effect on comparability.**
Remediation: add `residualTreatment` ∈ `["excluded-declared","grossed-up-declared"]`; add *"Two unit-cost observations are comparable only under the same residual treatment and the same metric-definition version."*

**31. Approval is structurally inferable — the exact thing the brief forbids.**
Evidence: `authorityRef` is required but there is no approval record, approver or approval timestamp; the rule lifecycle permits `approved → effective` with no evidencing event; `CostAllocationRun.actorRef` is **optional** on an object whose entire purpose is to be audit-citable.
Remediation: make `CostAllocationRun.required: actorRef, authorizationRef`; add `CostAllocationRuleRevision.required: approvalRecord {approverRef, approvedAt, approvalAuthorityRef}`, required for any transition into `approved` or `effective`; add *"Approval is evidenced by an approval record; lifecycle state never implies approval."* No fixture may assert `approved` or `effective` state. No rule in this dossier carries an approval record.
