# Isolated transaction experiment

This is a research prototype, not an installable Vercy metamodel, authorization service or production adapter. The complete independent Claude study, final boundary decision, schemas, native binding and frozen implementation audits remain outstanding. Do not use this file as a publication-readiness claim.

The experiment keeps an invented workspace value, immutable intent, retained retry key, effect receipt, attempt observations and a trusted test policy in one local SQLite database. BEGIN IMMEDIATE serializes current policy checks with the local effect and receipt. It avoids the unproved assumption that a file lock can atomically commit several independent files or an external operation. The scope follows SQLite's documented local transaction behavior; storage and filesystem guarantees remain dependencies.

Run `python test_transaction_spike.py` from this directory with Python 3.12 or a compatible interpreter. The executed reference environment used SQLite 3.53.1. All fixtures are synthetic and temporary. The test creates no network or external business effect. Fixture setup and inspection are privileged test helpers, not public authorization endpoints.

24 behavioral tests passed. They cover a repeated intent producing one effect, array-order conflict, equivalent object-key order, a fresh policy revision without changing intent, proposal refusal, rejection of a caller-supplied permission field, execution revocation, current cached-result disclosure, separate read/execute authority, wrong tenant/audience/epoch/action/resource, wrong actor/principal/purpose/session, expiry, resource-version conflicts, replay after an intervening legitimate change, rollback between effect and receipt, a lost response after commit, concurrent independent connections, retired keys, a missing database, three organization profiles, a new compensating request and preserved original intent bytes.

The first test run exposed unclosed SQLite connections during Windows temporary-file cleanup. The implementation now closes connections explicitly; the complete rerun passed. This was an experiment harness defect, not evidence of any production Vercy failure.

Important limits: the clock uses invented integer test times; sessions and policy admission are trusted fixture inputs; no real authentication, credential chain, complete delegation instrument, JSON Schema, native event export or asynchronous execution lifecycle is provided. Exception injection is not a power-loss test. The compensation case is a new version-guarded value change, not a complete compensation protocol. A missing record in a retained current store is not proof about a lost, restored or replaced store. The experiment refuses to create a new database on a missing execution path, and checks the configured epoch. Backups, host identity, fencing, audit admission and current-disclosure enforcement beyond this process remain unresolved production concerns.

Sources read for this experiment: [SQLite atomic commit](https://www.sqlite.org/atomiccommit.html), introduction and hardware assumptions; [SQLite transactions](https://www.sqlite.org/lang_transaction.html), sections 2.1–2.3 and error handling. These support using a real local transaction. They do not prove this experiment resilient to every crash, filesystem or external effect. The code is original; no SQLite source code is copied.
