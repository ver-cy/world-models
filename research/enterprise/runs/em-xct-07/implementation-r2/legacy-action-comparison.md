# Legacy action and capability seeds: additional reuse boundary

This selected comparison was added after the original common research brief. Neither provider's initial recommendation should be treated as having independently reviewed these documents. The two public 0.2.0 Markdown seeds were read in full; they are not the researched `spec.yaml` publications used for the two primary parents.

- [K1 Function & Capability](https://ver.cy/models/docs/activity-work/K1-function-and-capability.md) describes named functions, capability taxonomy, proficiency, agent attributions, evidence, capacity and requirements. A named `function` is a purpose an agent can fulfil, with a definition, domain and typical outputs.
- [K2 Act / Action](https://ver.cy/models/docs/activity-work/K2-act-action.md) describes an atomic recorded act and its `actClass`, participants, involved objects, observed outcome, responsibility and derivation. `actClass` is a typed verb with name, definition, domain and expected participants. The seed explicitly aligns act occurrences with the core Event concept.

The current research status inventory lists the corresponding WM-ACT-001 and WM-ACT-002 contours as queued, with no valid completed run recorded there. No `publication.json`/`spec.yaml` release for these two was found in the canonical publications inventory. That is distinct from the seeds being publicly readable. Their asserted conformance labels, wildcard imports, ownership statements and simplified projections are legacy declarations, not independently verified conformance or executable authority.

Both providers proposed a new reusable ActionDefinition. There is a real overlap with K2's actClass and K1's function vocabulary. The additional execution definition would constrain parameters, preconditions, effect boundary, version, current retirement and exact adapter behavior. The seed does not deliver that closed schema or executor. Accordingly:

1. Do not claim that action types or named functions are absent from Vercy.
2. Do not import a capability attribution as permission or an observed act as an executable request.
3. Compare a versioned execution-definition profile/refinement of the legacy actClass with a new sibling definition master. The difference must be exact signature/effect semantics and identity governance, not just renaming.
4. Avoid silently inheriting the seed's broad assertion that the acting agent owns all act records. The authority to issue executor receipts and the right to disclose them are explicit host contracts.
5. Preserve the D1 external-definition option until both providers receive the same supplemental ownership/legacy/native facts. The first implementation may pin a governed external definition without claiming to solve an entire enterprise action registry.
