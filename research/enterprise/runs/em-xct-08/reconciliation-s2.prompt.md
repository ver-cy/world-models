1. UNKNOWN GENERATION: unknown is not a joinable lineage value. Occurrences with unknown record generation are retained and counted but are `continuity-unknown`, without operative mapping pins. Active mapping requires an explicit non-null record generation and generation evidence: source incarnation, source non-reuse guarantee, or explicit steward attestation. A source non-reuse guarantee permits a declared stable generation with that evidence, not implicit equality of unknowns. Key equality, digest equality or a new capture never establishes continuity. Source-instance generation, record generation and sync epoch remain distinct. Mapping anchors include full qualified source key and both source/record generations. Historical unknown occurrences remain unchanged when later evidence arrives.

2. PINS AND REPLAY: register computes mapping outcomes once inside the commit transaction. Client content digest covers only immutable supplied acquisition content (scope/epoch/batch key, ordered record descriptors, round/page declaration, token evidence and declared mapping purpose), NOT computed mapping pins, attempt ID, expected head or fence. Expected head/fence and optional expected mapping revision are admission preconditions, not retry body identity. Receipt stores the original computed (mappingId, stateRevision), target-catalogue/policy pin and result status per occurrence. An exact retry retrieves the old result after current authorization; it never recomputes pins. Same key with changed acquisition content is a restricted conflict. Stable batch key is scope/epoch-wide, NOT expanded with writer identity (which could allow a second writer to recommit the same acquisition). Source key extraction/schema/interpretation change still creates a new acquisition scope.

3. MAPPING UNIQUENESS AND KINDS: every transition into active, including disputed→active, checks uniqueness per (complete lineage, purpose). Replacement uses new mapping ID and explicit correction link; old mapping must be non-active before replacement activates. Local atomic retract-and-activate is allowed; an observed zero-active interval is allowed; two active claims never are. Mapping anchors never mutate. SourceObjectKind comes from trusted scope interpretation, target kind from a pinned host catalogue revision, and allowed aboutness pair from pinned host policy. Later target-catalogue reclassification makes new pinning insufficient-context until steward review; it cannot silently preserve a false kind or rewrite old pins. Corrections of occurrences carry an asserted-by identity and source-asserted or steward-asserted basis; an operator cannot impersonate the source. This package records host-verified assertions, not live identity proof.

4. ACKNOWLEDGEMENT: authenticate and authorize the specific operation before existence lookup. Revoked/unauthorized requests get one generic response regardless of key existence; host denial telemetry stays separate. Write-only caller may receive a minimal acknowledgement for a new successful commit or identical retry ONLY when its authenticated principal equals the original committer's principal. Current read permission is required for historical lookup, including after epoch close. An old body submitted to the closed-epoch COMMIT API is refused uniformly; a separate READ operation can retrieve retained history. Closing an epoch forbids new effects, not separately authorized historical access. No automatic transfer of write-only recovery rights between principals.

A local DB reopening after an ordinary process crash is distinct from restore: host must establish current ownership and continuity. This reference cannot detect a coherent stale copy or cloned live DB; trusted storage/host continuity remains external. Do not label archive validation an authenticated/latest-state proof.
