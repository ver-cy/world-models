# Enterprise identity-assertion profile: design candidate

This is a design candidate awaiting independent study reconciliation and audit. It is not a published or validated implementation.

Publication form: reuse WM-XCT-011 qualified identifier rules and profile WM-XCT-036 assertions. Preserve the complete existing semantic model and its historic source/provider holds. Publish a separately versioned, bounded profile and explicit snapshot binding as an additive increment. No new subject-model ID. A derived read-only resolution view is an adapter, not an authoritative IdentityResolution object and not part of the subject model's core responsibility.

Each native object represents exactly one identity assertion with its own stable ID. Its immutable endpoints, dimension, purpose, interval and predicate are separate from an append-only revision history. Correction to an endpoint retracts the old assertion and proposes another; it never changes the referent of an old assertion ID. Source assignment occurrences distinguish reused lexical identifiers over time. Strings are compared exactly; normalization requires a separate explicit source-governed profile and is not silently applied.

An external person identifier can denote a Person. An account identifier denotes an Account, not a Person. A Git or tracker account-to-person link therefore needs a typed account-holder/attribution relation and must not become an identity assertion, even after human approval. The minimum identity profile will reject or defer such cross-kind claims; the startup acceptance data must state whether a source exports a person reference or an account reference. A Git author label is only candidate evidence. This is a stricter interpretation than collapsing all HR/Git/tracker IDs into person identity.

The first executable scope is a narrow identity assertion, not probabilistic matching, account ownership, destructive merge/split, global owl:sameAs export, general identifier normalization, authenticated policy service or globally complete identity registry. Three independently assigned person-reference IDs may point at one local subject URI if their meaning and evidence justify that claim. Accounts must stay distinct.

Revisions carry a distinct revision ID, previous revision digest, recordedAt, effectiveAt, actor, state, reason and evidence. Recorded times strictly increase. Effective times may correct a past assertion; a read uses both valid time and knowledge time. Withdrawal never deletes evidence. Retraction is terminal for an assertion; a corrected claim has a new assertion ID. These are local operational rules, not inferred PROV conformance.

Policy is independently supplied and digest-pinned. It states the adopting Dimension, purpose, permitted issuers/types, actors and allowed lifecycle actions, validity window and current read purpose. The example validator checks the structure and declared policy constraints. Authentication, evidence truth, completeness, actual read/write enforcement and retention remain integration responsibilities and must never be implied by a passing fixture.

A resolution view compares exact qualified keys and includes only directly asserted endpoints. It does not take transitive closure. Results are scoped to the provided, identified input set and chosen valid/knowledge times; a single surviving claim is not global proof of uniqueness. Conflicting active subjects or a disputed relevant claim remain contested. Proposed evidence remains candidate. No admissible link returns unknown. Historical acceptance does not confer present authorization or disclosure rights.

Required negative cases: issuer/tenant collision; reused assignment period; email/name-only evidence; source Account versus Person; service account versus Person; unqualified ID; hidden normalization; equal-authority conflict; unknown versus explicit rejection; stale or unauthorized revision; predecessor or endpoint mutation; duplicate import with divergent content; retraction history loss; incompatible schema version; dropped fields on round-trip; V3-valid but invalid nested snapshot.
