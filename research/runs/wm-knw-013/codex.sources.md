# WM-KNW-013 Codex source notes

The synthesis treats a Constraint / Requirement Rule as one versioned,
formal or formalizable normative expression with explicit rule kind, authority,
applicability and evaluation semantics. ISO/IEC/IEEE 29148 and SysML provide
requirements engineering and traceability context. OCL, SBVR and DMN provide
model constraints, business vocabulary and decision logic. None supplies a
universal rule profile for every domain.

SHACL, OWL, SPARQL, JSON Schema and Schematron define different validation,
inference and query semantics. ODRL, LegalRuleML and XACML cover rights, legal
norms and authorization policy. OSCAL and NIST SP 800-53 cover controls and
assessments. OpenAPI and Rego add API-contract and executable-policy views.
Each is an interoperable projection rather than the rule identity itself.

The model therefore separates syntax validity, predicate satisfaction,
verification, validation, conformance, compliance, safety, legal effect and
accountable decision. It preserves source and normalized expressions,
requirement links, exceptions, conflicts, precedence and engine results as
source-qualified records. RFC 3339 provides timestamps with seconds and an
explicit offset; RFC 8785 supports deterministic JSON serialization.
