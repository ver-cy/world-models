Both providers independently classified the model as an `aggregate`: a
versioned statement of intention that owns its planned actions, schedule
entries, recurrence sets, commitments and baselines. Agent identity, completed
acts, standing process definitions, project governance and resource master data
remain sibling references rather than copied masters.

The no-tools adjudication retained Claude as the structural base and accepted
Grok additions for iTIP scheduling methods and message sequencing, RFC 9253
plan hierarchy and typed relationship integrity, and the
`fn-split-this-and-future` operation. It recorded sixteen decisions and no
critical conflict. ISO 21502 was not admitted as a normative baseline authority
because only catalogue-level, paywalled evidence was available.

Both provider runs used the same frozen contract and clean input commit
`d7000c9aecd3a878757f6ea0a227cf06728a3655`. Grok returned its substantive
answer in an alternate provider envelope; the raw wrapper remains outside Git.
A no-tools pass normalized only the transport shape, made no semantic repairs,
and renamed one cross-grain duplicate identifier from `schedule-entry` to
`function-schedule-entry`. Both provider results and the synthesis pass schema
and semantic validation.

Live source and version-pin verification, primary-text checks for GAO-16-89G
and NARA GRS 5.1, autonomous-agent and non-US retention profile validation, and
the prohibition on treating ISO 21502 as a normative authority remain explicit
publication holds. See `synthesis-plan.json`, `adjudication.json`,
`comparison.json` and `synthesis.validation.json`.
