# Six-stream Vercy research protocol

This directory defines the non-overlapping execution contract for the 312
subject models that were still queued after sequence 89 on 2026-09-04.

## Fixed partition

The source is `research/status.csv` at base commit
`4aa459710272b9425b19f870eada6005ec7abc3b`. Each queued row is assigned by:

`stream = ((sequence - 90) mod 6) + 1`

This produces six sets of exactly 52 model IDs. The model ID list in each
`workstreams/stream-0N/SCOPE.csv` is authoritative. A worker must never research,
generate, edit, commit or publish a model absent from its own scope.

## Per-model worker write boundary

For one assigned model, a worker may change only:

- `research/runs/<assigned-model-id-lowercase>/**`;
- `publications/<assigned-model-slug>/**` generated by the publisher;
- its own `workstreams/stream-0N/LOG.md` and `STATE.json`.

The worker must not change shared queue, registry, tool or policy files,
including `research/status.csv`, `research/queue.csv`, `provider-policy.json`,
`planning/**`, `models/**`, `tools/**` or another stream directory. A required
shared change is logged as a proposal and left for the coordinator.

Each completed model is one secret-safe commit on the stream branch. The commit
must contain a valid synthesis, no critical conflict, the no-tools audit,
comparison/adjudication evidence and a generated published package whose
research state remains `reviewable-draft`. Raw provider wrappers and incomplete
prompts/manifests are never committed.

## Provider isolation

The current owner-authorized policy in `research/provider-policy.json` is
Claude-only with Grok waived. Workers must not call Grok unless the owner later
revokes that policy explicitly and the repository policy is updated first.

Before every Claude request, a worker must acquire the shared `claude` lease:

```powershell
& .\tools\workstream_lease.ps1 acquire claude stream-01
```

Replace the stream ID as appropriate. Release it immediately after the provider
process reaches a verified terminal state, including failure:

```powershell
& .\tools\workstream_lease.ps1 release claude stream-01
```

Only one request may exist globally. A busy or malformed lease is fail-closed:
do not start a second request, do not remove another stream's lease and do not
auto-steal a stale lease. Use the waiting time for source preparation, local
validation or synthesis work that does not call a provider.

## Integration and production isolation

Streams 02-06 never touch the canonical integration worktree, the `ver.cy` site
working copy, SSH, Bitrix or production. They push their branch and log the
ready commit hash in their own `LOG.md`.

Only stream 01 may integrate or deploy, and only while holding the corresponding
lease. It works in the canonical integration worktree
`R:\02_PROJECTS\02_Meta_Models_Platforms\Ver.cy\current\ver-cy\world-models`
on `feat/mega-model-registry`.

For each ready worker commit, stream 01 must:

1. acquire `integration`;
2. verify the canonical worktree is clean and synchronized;
3. fetch the worker branch and apply exactly one model commit without committing;
4. verify its changed paths satisfy that worker's write boundary;
5. regenerate `research/status.csv`, validate the model and create one canonical
   per-model commit;
6. acquire `production-deploy`, copy only that publication package to the site
   working copy, rebuild the Bitrix import and generated site artifacts, deploy,
   migrate and run HTTP plus SEO/AEO/GEO checks;
7. push `feat/mega-model-registry` only after every production check passes;
8. release `production-deploy`, then `integration`.

No later ready model is integrated while a failure is unresolved. This keeps all
shared status, Git and production mutations strictly serial while research and
local synthesis remain distributed.

## Failure rules

Stop the affected stream fail-closed on authentication/subscription, malformed
or semantically invalid provider output, critical conflict, local validation,
Git, integration or deployment failure. Do not skip to another assigned model.
Record the exact failure in the stream log without secrets. Other streams may
continue only if they do not need the failed shared resource.
