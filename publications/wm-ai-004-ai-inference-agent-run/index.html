AI Inference / Agent Run

find-run-identifier

Authoritative run identifier

Which identifier authoritatively names this run, which system issued it, how it behaves under retries and asynchronous retrieval, and which vendor-native identifiers are kept alongside it. OpenTelemetry marks gen_ai.response.id as Required only for fetch_response operations, Anthropic returns a msg_ prefixed message id, and Amazon Bedrock records a requestId; none of these is a governed global identifier, so the adopting Dimension must state its priority order.

    Expected answer

    • Identifier literal
    • Identifier scheme or namespace
  2. When the executing provider returns no run identifier, what identifier does the adopting Dimension mint, and how is uniqueness guaranteed?identity
    Expected answer
    • Minting rule (UUID or ULID)
    • Minting authority
    • Uniqueness scope
  3. Does the identifier stay stable across retries, streaming resumption and later asynchronous result retrieval, or does each attempt receive a new one?constraint
    Expected answer
    • Stability rule
    • Attempt number
    • Identifier of the superseded attempt
  4. Which vendor-native identifiers are retained beside the authoritative identifier, and what is each one good for?interoperability
    Expected answer
    • Provider response identifier
    • Provider request identifier
    • Mapping note per identifier

OpenTelemetry marks gen_ai.input.messages and gen_ai.system_instructions as opt-in with explicit sensitive-data warnings, and Bedrock externalises any body over 100 KB to object storage, so the run record must distinguish inline content from a reference plus digest.

Input segment provenance and trust level

For each segment of the model's context, where it came from and how far it may be trusted. MCP states that tool annotations and tool results must be treated as untrusted unless the server is trusted, and directs clients to validate tool results before passing them to the model; a run record that flattens user text, retrieved documents and tool output into one undifferentiated context loses the evidence needed to investigate an injection.

    Expected answer

find-decoding-params-and-reproducibility

Decoding parameters and reproducibility limits

Which sampling and decoding parameters were in force and what actually prevents an identical re-execution. Anthropic marks temperature, top_p and top_k as deprecated for newer models, so a model that assumes these are always present and always determinative will mis-record reproducibility. The run references an immutable configuration snapshot rather than restating its content.

    Expected answer
    • Reproducibility class
    • Non-determinism sources
    • Seed value if supported
  3. How is a parameter recorded when the provider has deprecated, capped or silently ignored it for the selected model?exception
    Expected answer
    • Parameter disposition code
    • Requested value
    • Effective value
  4. Which configuration snapshot does the run reference, and is that snapshot immutable and content-addressed?provenance
    Expected answer

    • Per-call override set

PROV associates the activity with an agent and optionally a plan. OpenInference records agent.name. The run also records the configuration identifiers needed for reproducibility (prompt version, tool definitions version, policy version, decoding profile) as references to WM-AI-005 rather than embedding the configuration catalogue.

Step decomposition and deliberation capture

The ordered, nested set of steps making up the run, and the treatment of intermediate reasoning. OpenTelemetry defines plan spans for task decomposition and counts inference_calls and tool_calls per agent invocation; Anthropic returns thinking blocks as first-class content. lay-tool-and-environmentTool and environment interaction2 findings

Calls the run made out to tools, servers and knowledge sources, and the evidence retained about each.

find-tool-call-record

Tool call record and effect character

For each tool invocation: what was called, with what arguments, what came back, whether it failed, and what side-effect character the tool declared. MCP separates protocol errors (JSON-RPC error) from tool execution errors (isError true in the result) and warns that annotations are untrusted unless the server is trusted, so the record must keep the declaration and the trust judgement apart. Retries, timeouts and multi-round-trip input-required flows must be linked to one logical call.

Questions
  1. For each tool call, which tool on which server was invoked, with which arguments, and what did it return?process
    Expected answer
    • Tool call identifier
    • Tool name and server canonical URI
    • Argument object
    • Result content and structured content
  2. Did the call fail at protocol level or return an execution error, and how is that distinction preserved in the record?exception
    Expected answer
    • Protocol error code and message
    • Execution error flag
    • Low-cardinality error type
  3. What side-effect character did the tool declare - read-only, destructive, idempotent, open-world - and was that declaration treated as trusted?security
    Expected answer
    • Declared annotation set
    • Server trust determination
    • Observed effect classification
  4. How are retries, timeouts, cancellations and input-required round trips of the same logical call linked together?state
    Expected answer
    • Logical call identifier
    • Attempt sequence
    • Timeout or cancellation reason

Every instant on the run, in a single governed format, with event time kept apart from observation, ingestion and billing-bucket time. RFC 3339 requires an explicit numeric offset or Z and reserves -00:00 for an unknown local offset. Anthropic's usage reporting is bucketed with a stated freshness lag, so cost timestamps are demonstrably not the same clock as execution timestamps.

find-rare-endings-and-degenerate-runs

These cases are easy to omit from naive chat-only schemas.
