Currency / Monetary Value

Provide an embeddable declaration of a monetary value on a host object: an exact decimal amount bound inseparably to an identified currency, with declared precision and rounding intent, an optional valuation date and conversion reference, and explicit value states, so that an agent can read, validate and reproduce monetary context without inferring any of it.

money-core-catalogue-binding

Authoritative currency catalogue and pinned edition

A currency code only identifies a currency relative to a named catalogue, a specific list within it and a published edition. The ISO 4217 lists carry an explicit published-edition attribute and are amended over time, so a declaration must record which catalogue, which list and which edition it was resolved against, and must be able to verify the retained snapshot before resolving anything against it.

money-core-exact-decimal

Exact decimal amount as sign, coefficient and scale

The amount is an exact decimal value: a sign, a non-negative integer coefficient and a scale expressed as a non-positive power of ten. Binary floating point is rejected as the canonical representation because it cannot represent common decimal fractions exactly. Digit bounds on coefficient and scale are declared by the host or profile, and a value that cannot be represented exactly at the declared scale is rejected rather than rounded away.

money-core-lexical-canonical

The canonical lexical form of the amount is fixed and distinct from any rendered display string. Because numerically equal decimal representations can differ visibly, the declaration must state whether trailing zeros are significant, and must state how zero and a signed zero are treated, so that round-tripping preserves sign, coefficient and scale.

money-core-pair-integrity

Amount and currency inseparability on the host object

Amount, currency reference and declared scale form one indivisible declaration: published monetary datatypes bind them into a single type, and a value interchanged without a known currency code is not interpretable. The host object owns the business meaning, including what a negative amount signifies, and projections that split the parts into separate fields must still assert the binding.

money-core-value-states

Declared determinacy: exact point, interval, approximate or explicitly absent

A monetary field must be able to say what kind of assertion it is making. Published monetary vocabularies support a value or a bounded range, and published absent-value vocabularies distinguish unknown, masked, not-applicable, unsupported and error. The declaration therefore carries an explicit determinacy state, so an absent or unknown value is never silently expressed as zero and an interval is never collapsed to a point.

Declared precision and scale versus observed digits
