identity-and-identifiersIdentity and Identifiers3 findings

place-record-identity

Place record identity and identifier minting

A gazetteer place is identified by a persistent, opaque identifier that survives renaming, reclassification and geometry revision. Authoritative master-system identifiers (GNIS Feature ID, INSPIRE inspireId, national gazetteer key) take precedence; a governed HTTP URI is minted for web resolution; only where no external authority exists does the adopting Dimension mint a UUID or ULID. A date, a name or a coordinate pair is never the identifier.

Questions
  1. Which authoritative master system already identifies this place, and what is its identifier value and namespace?identity
    Expected answer
    • master system name and register URI
    • native identifier value
    • identifier scheme or namespace URI
    • evidence that the identifier is the authority's primary key
  2. What persistent HTTP URI resolves to this place record, and who guarantees that it will not be reused?identity
    Expected answer
    • resolvable HTTPS URI
    • namespace controller
    • persistence commitment or policy URI
    • content-negotiation targets
  3. Does the identifier remain unchanged when the place is renamed, reclassified or re-delimited, and what evidence supports that?constraint
    Expected answer
    • identifier stability policy reference
    • worked example of a rename that preserved the identifier
    • list of change classes that force a new identifier
  4. How are two candidate records determined to denote the same place rather than two distinct places?validation
    Expected answer
    • sameness criteria (type, extent overlap, name evidence)
    • adjudication rule and reviewer role
    • merge decision record reference

geographic-identifier-and-indirect-referencing

Geographic identifier, location type and indirect spatial referencing

ISO 19112 positions a gazetteer as a directory of geographic identifiers describing location instances, where a location type defines the semantics of the instances it admits. The place record must therefore declare which gazetteer register and which location type it belongs to, and must support indirect referencing — resolving a label or code to a position rather than carrying coordinates alone.

gazetteer-register-membership-and-item-status

Gazetteer membership and register item

ISO 19112:2019 defines a gazetteer as a register of location instances of one or more location sub-types containing some information regarding position, and recognises the gazetteer as a sub-type of ISO 19135-1 Register, with Location a RegisterItem. OGC WFS-G exposes gazetteer metadata and location instances over a feature service. A place may appear in more than one gazetteer.

toponym-spelling-script-and-transliteration

Toponym form, language, script and transliteration

A name is not a string: INSPIRE models GeographicalName with language, and one or more SpellingOfName each carrying text, ISO 15924 script and an optional transliteration scheme, plus optional PronunciationOfName with IPA and a sound link. Romanized forms must be traceable to the romanization system used, which is a standing UNGEGN concern.

name-status-nativeness-and-preference

Name status, nativeness and preference

Names carry a status (official, standardised, historical, variant) and a nativeness (endonym or exonym), and exactly one preferred label is normally selected per audience. GNIS permits only one official name per feature for Federal use with variants retained; Getty TGN requires a preferred name plus vernacular and historical variants; GeoNames types names as official, short, colloquial or historical.

deprecated-derogatory-and-community-restricted-names

Historical, deprecated and sensitive names

TGN retains historical, misspelled, pejorative and avoid-use names for retrieval of legacy materials and flags them so they are not used for new indexing. GNIS marks obsolete names and vanished features as historical without implying age. GeoNames records historical and colloquial alternate-name types. These forms remain in the name set rather than being deleted.

place-type-classificationPlace Type Classification2 findings

Assigning and governing the feature or place type of the place, including local types and type change over time.

feature-type-and-local-type-classification

Feature type, local type and classification change

Every governed place carries at least one type drawn from a resolvable vocabulary. INSPIRE separates a coarse NamedPlaceTypeValue from a free localType; LPF requires broad fclasses (A, H, L, P, R, S, T) plus optional vocabulary-typed types with source labels; GeoNames uses featureClass plus featureCode; Getty TGN requires a preferred place type. Types are temporally scoped because a village can become a suburb.

administrative-versus-physical-facet

Administrative versus physical facet

TGN distinguishes Administrative records (inhabited places, nations, empires) from Physical records (mountains, rivers, oceans) and discourages a Both flag. Physical features that cross political boundaries are placed under the next containing hierarchical level. GNIS after 2021 focuses on natural features, unincorporated populated places and selected hydrographic and reservoir classes, and removed most cultural classes.

representative-position-and-geometry-set

Representative position and multiple geometries

A place may carry a representative point, a bounding box, one or more detailed geometries, or no geometry at all. GeoSPARQL distinguishes hasGeometry from hasDefaultGeometry and provides derived centroid and area; LPF permits several temporally scoped geometries with per-geometry certainty and citations, or a null geometry; Getty TGN records point and bounding-box coordinates.

crs-declaration-and-coordinate-encoding

CRS declaration and coordinate encoding constraints

Coordinates are meaningless without a declared spatial reference. RFC 7946 fixes GeoJSON to WGS 84 with longitude before latitude; OGC API - Features defaults to OGC:CRS84 and requires explicit CRS negotiation for alternatives; GeoSPARQL carries CRS identity inside geometry literals; the SDW best practices require publishers to state how coordinate values are encoded and to choose a CRS suited to users.

positional-accuracy-resolution-and-viewing-scale

Positional accuracy, resolution and viewing-scale bounds

The SDW best practices require describing positional accuracy and providing geometries at an appropriate level of accuracy, precision and size; INSPIRE NamedPlace carries mostDetailedViewingScale and leastDetailedViewingScale to bound legitimate display. Precision of coordinates must never be read as accuracy, and generalized coordinates must be labelled as such.

existence-period-and-temporal-uncertainty

Existence period and temporal uncertainty

Places begin, change and cease. LPF expresses temporal scope as timespans with start and end, each expressible as 'in', 'earliest' or 'latest', plus named periods, duration, label and certainty; GNIS marks features as historical when they no longer exist. The model must accept open, approximate and disjoint existence intervals without forcing a false precise date.

Places are discovered to be duplicates, are divided, are absorbed or are found never to have existed. Who's On First records supersedes and superseded_by as arrays, allowing one-to-many and many-to-one succession; Getty TGN defines rules for merging, moving and deleting records. Identifiers must not be silently reused or hard-deleted, because external systems already cite them.

place-hierarchy-and-topologyHierarchy and Topology2 findings

Partitive and administrative containment, and formal or informal spatial relations to other places.

partitive-and-administrative-hierarchy

Partitive and administrative hierarchy

Places sit in hierarchies: GeoNames gives parentFeature and parentADM1 to parentADM4; Who's On First gives parent_id, a hierarchy of ancestor sets and a flattened belongsto; Getty TGN distinguishes preferred from non-preferred parents; schema.org offers containedInPlace and containsPlace. Multiple concurrent hierarchies (administrative, statistical, ecclesiastical, historical) must coexist without one being privileged silently.

    Expected answer
    • hierarchy scheme list
    • ancestor chain per scheme
    • flattened ancestor set
  3. How is an unknown, complicated, contested or multiple parentage recorded without asserting a false parent?exception
    Expected answer
    • sentinel or state code
    • explanatory note
    • review trigger
  4. What prevents cycles, orphans and type-inconsistent parenthood in the hierarchy?validation
    Expected answer

    • cycle detection test

topological-and-associative-relations

Topological and associative relations

Beyond containment, places touch, overlap, adjoin, succeed and are functionally associated. GeoSPARQL provides Simple Features, Egenhofer and RCC8 relation families; schema.org exposes DE-9IM-derived geo relations; Who's On First records breaches where same-placetype records intersect; LPF relations carry a vocabulary relationType with temporal scope, certainty and citations.

  3. Do same-type places overlap where they should partition space, and how is that anomaly recorded?quality
    Expected answer

  4. Where no geometry exists, how is relative position expressed and against which reference place?spatial

cross-gazetteer-concordanceCross-Gazetteer Concordance1 findings

Matching this place to records in other gazetteers and authorities, with explicit match strength and evidence.

external-identifier-concordance-and-match-confidence

External identifier concordance and match confidence

LPF distinguishes exactMatch, closeMatch, primaryTopicOf and seeAlso; Who's On First keeps a concordances hash of identifiers from other sources; schema.org uses sameAs. Asserting exact identity where only a close match is warranted is a common and damaging error, so match strength, matcher and evidence must be recorded and revisable.

encoding-and-service-projectionEncoding and Service Projection1 findings

Rendering the format-neutral record into exchange encodings and query interfaces without changing its semantics.

exchange-encodings-and-service-contract

Exchange encodings, profile conformance and query-service contract

The same place record projects into GML per the INSPIRE GN application schema, GeoJSON per RFC 7946, Linked Places Format as JSON-LD that is simultaneously valid GeoJSON, and RDF per GeoSPARQL — and is queried through interfaces such as OGC API - Features with /collections and /items paths, bbox, datetime and limit parameters and required link relations. Each projection loses or constrains something, and the losses must be declared.

sensitivity-and-access-controlSensitivity and Access Control1 findings

Deciding when a location must be generalized, withheld or restricted, and disclosing what was done.

sensitive-location-generalization-and-access

Sensitivity classification, generalization and disclosure

GBIF defines graded sensitivity categories with matching coordinate generalization (region only, 0.1, 0.01 and 0.001 degrees), prefers grid-based generalization over randomization, requires that withholding and generalization be disclosed in dedicated fields, places the sensitivity decision with the data provider, and requires a recorded date for reviewing the sensitivity status. The same pattern governs culturally restricted, security-sensitive and privacy-sensitive places.

Validation, conformance testing and fitness for use

GeoSPARQL 1.1 ships SHACL shapes for RDF validation; INSPIRE publishes validation resources for the GN schema; LPF v1.3 makes fclasses required because it improves reconciliation; the SDW best practices call for exposing validation schemas online. retention-deletion-and-archivalRetention, Deletion and Archival1 findings

How long records and their versions are kept, and how removal is performed without breaking external citations.

retention-tombstoning-and-erasure

Retention, tombstoning and lawful erasure

Gazetteer identifiers are cited by external systems, so removal is normally deprecation with a tombstone plus a superseded-by pointer, not deletion; Getty TGN treats deletion as a governed editorial action with retained history, GNIS retains historical features, and persistent-URI practice forbids identifier reuse. Genuine erasure obligations (for example personal data embedded in a note) must be satisfied without destroying the identifier or the succession chain.

Publication holds

  • ISO 19112:2019 normative text was reached by neither provider (ISO catalogue returned HTTP 403 for one, paywalled for the other). Class names, attribute names, cardinalities and the 2003-to-2019 rename set are unverified, and the two providers report different vocabularies for the same construct. Verify against the purchased standard or the ISO/TC 211 register before publishing any wording that a reader could mistake for a conformance statement.
  • Live-URL and version-pin verification for every accepted source. Specifically: the US BGN Principles, Policies and Procedures edition date was not machine-extractable; the INSPIRE Geographical Names Technical Guidelines are cited by the two providers as a versioned PDF (v3.1.0, 2024-07-31) and as a knowledge-base landing page and must be reconciled to one pinned artifact; and the three grok-sourced additions carry only tier-2 or accessed-page evidence.
  • Multi-profile domain validation is incomplete. The model is exercised only against US BGN/GNIS, INSPIRE/EU regulatory practice and compiled gazetteers (GeoNames, Getty TGN, Who's On First, Linked Places Format). Run it against at least one non-US, non-EU national names authority and one historical or linked-pasts gazetteer profile before publication, and re-test the ISO 19112 descriptive-position case against INSPIRE's mandatory NamedPlace geometry to confirm the optional-geometry-with-absence-reason resolution holds in both profiles.
  • Indigenous and culturally restricted place-name governance is a gap the base declares and the accepted grok finding only partially fills. No Indigenous data-sovereignty instrument (CARE Principles, UNDRIP as applied to toponyms) was examined by either provider. Do not present the sensitivity and access layer as canonical, and mark the community-warrant question as provisional.
  • Temporal-uncertainty syntax is ungrounded: the intended EDTF (ISO 8601-2) grounding failed with HTTP 403, leaving approximate, uncertain and unspecified-digit dates supported only by the Linked Places 'when' object. Publish no specific uncertainty syntax.
  • Sensitivity categories and their thresholds derive from a biodiversity-occurrence context expressed in decimal degrees, and no national security-classification regime was consulted, so the mapping from sensitivity category to government classification level is undefined and the thresholds are unvalidated at high latitudes and for cultural restriction.

Deferred research

  • NGA GNS field dictionary (UFI/UNI, name type, designation code) — neither provider retrieved it, and it is the usual governing register for non-US official names, so the officiality and identifier findings currently rest on US and EU practice alone.
  • IHO SCUFN undersea feature names and IAU WGPSN planetary nomenclature: both providers exclude marine, undersea and extraterrestrial naming regimes, which may require additional authority and classification structure.
  • Homograph disambiguation (parent string, qualifier, noted-homograph flag) and a persistent term identifier per name form distinct from the place identifier — to be folded into the base toponymy findings rather than added as a duplicate node.
  • INSPIRE relatedSpatialObject-style cross-theme linking: how a place record points at the same real-world entity held in a declared sibling model (administrative unit, built work, transport network) without collapsing the two, which the base boundary notes presuppose but no base finding governs.
  • Statutory suppression of a feature's very existence, as distinct from coordinate generalization — evidenced for caves by the Federal Cave Resources Protection Act and 43 CFR Part 37 — including how it must be enforced across nearby, reverse-geocode and bulk-dump paths.
  • ISO 19155 Place Identifier architecture, unmodelled by both providers, and its relationship to the identifier priority and concordance findings.
  • ADL Gazetteer Content Standard and Feature Type Thesaurus, and the UNGEGN Resolution 4 minimum digital-exchange set (name, feature type, location) as a candidate normative publishability floor.
  • Boundary edge confirmation for legendary and fictional places excluded versus lost, planned-but-unbuilt and archaeologically attested places included, plus multilingual collation authority and crowd-sourced contribution moderation, vandalism detection and trust scoring, all of which both providers list as untreated.
