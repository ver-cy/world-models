# Migration

Same-version import/export preserves all records, pins, kinds and unknowns. import_snapshot checks history consistency only; use validate_extension against the trusted current root and admit every appended row before live acceptance. migrate refuses every different target version: no automatic legacy owner/confidence conversion, lost provenance, epistemic upgrade or probability invention. Stage legacy candidates externally with exact source evidence and explicit human mapping. A changed source/claim/method identity must not inherit old support. Retain old package bytes for rollback; old software cannot safely interpret an unknown newer schema.

Import/migration/native snapshot checks require explicit trusted `now`; offline validation without it is not live admission. Retained pins must stay in the same reference field. Genesis and changes to label/basis/activity of a non-insufficient assessment require a current active dependency closure without unavailable/mismatched Captures. Corrections need a different review Activity ID first registered after the prior assessment; its revision 1 receipt must not predate explicit basis receipts. Import/snapshot configuration must be valid at trusted now. Read the exact vercy-python-json-v1 encoding and operational bounds in model-spec.md.
