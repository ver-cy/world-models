## Convergence adopted

Both amendments independently support:

1. A **new versioned operation-definition sibling**. Claude calls it OperationDefinition; Grok retains ActionDefinition. Adopt the public name **ActionDefinition**. K2 actClass is an optional descriptive crosswalk, not an unvalidated runtime inheritance. K1 function/capability must not become permission. A definition has useful independent governance and retirement semantics; it is more than a label or verb taxonomy.
2. An **independently identified immutable ActionRequest**, projected as a real native object. Claude expressly withdraws its original acceptance-Event/key-slot subject design. Events refer to the actual request object; key hashes remain payload/control data.
3. **External standing authority**, without a new DelegationMandate or DelegatedExecutionGrant master in this package. Both withdraw the duplicate first-increment mandate/profile proposals. Reference the existing control/mandate basis and retain fresh host decision evidence separately. A source WriteGrant, stewardship duty or source priority is not execution authority.
4. **Current exact scope containment** over separately supplied principal and delegate scopes, with host-verified issuer standing. No delegated boolean, arbitrary chain, impersonation or implicit widening. `maxUses` is deferred unless a genuine authoritative counter is implemented.
5. **A single local transaction** for the synthetic effect, key binding and receipt. Claude withdraws the provenance-scan/file-lock guarantee. Both recognize coherent snapshot rollback as a remaining continuity problem.
6. **Retryable current-policy denial** for pending requests until deadline/cancellation, a serialized cancel/execute race, compensation as a new version-guarded request, and uniform outward responses for readers denied access.

This is sufficient to start a bounded implementation. Do not start another general research round merely to seek complete verbal consensus. Preserve D1 as the earlier proposal; implement the chosen boundary and take the actual frozen package to the two required independent implementation audits.

## Corrections retained instead of blindly adopting the amendments

- **A committed request does not become expired on late replay.** Both responses use expired language too broadly. The deadline prevents a first effect while pending. A later currently authorized receipt read preserves the original committed state. A replay endpoint may refuse new dispatch after the deadline, but must not append an expiry disposition to a committed request. Tests must distinguish pending expiry from late lookup of a completed request.
- **Choose half-open time windows.** Claude still writes `t <= deadline`. Use `validFrom <= t < validUntil` and `t < expiresAt` for first effect, consistently with D1 and the existing Enterprise profiles. Test the exact boundary.
- **Keep execution and disclosure independently governed.** Claude suggests preserving minimal status-read as a mitigation for a caller minting a new key after a withheld result. That is a possible host policy, not a model permission grant. The package must support execute-only cases with uniform withheld output. A new key expresses a new intent; a lost response is not authorization to create one automatically. Cross-key duplicate-intent prevention is outside the simple retained-key guarantee.
- **Use a single occurrence vocabulary.** Transport delivery, a current-policy execution try and a committed effect differ. Grok says each delivery may append an attempt while later defining attempt as an execution try; Claude removes their identities despite an event history. The implementation will define explicit delivery/try evidence, with native event identity when retained, and a separate unique effect/receipt. It must not use one count for all three.
- **No authoritative `unknown` state for the atomic local adapter.** Grok still allows an in-flight try to park unknown and lists `effect-unknown`. Treat caller uncertainty as an observation, not permission to retry an absent effect after untrusted restoration. Pending/committed/terminal local truth comes only from the authoritative store. General remote reconciliation is deferred.
- **An external mandate reference is not an exact imported schema.** The ownership publication supplies a concept and declarative requirements, not a complete executable record type. Host fixture records must have explicit closed scopes, issuer-standing evidence and reference pins. Do not claim that a invented record satisfies a standardized WM-XCT-001 mandate schema or that the parent currently verifies it. If audience/purpose cannot be established, deny.
- **Depth must be defined, not guessed from a number.** Claude uses subdelegation-depth 0 while Grok says chainDepth 1. Use a named direct-representation mode, no further delegation, and explicit actor/principal fields. If a numeric depth is exported, define which edge it counts and test it.
- **A reference fixture's master can be selected within this task.** Adopt one SQLite master for the synthetic execution fixture and label native exports as evidence with export time and sequence. Vercy's actual production host may implement another conforming transaction boundary. This is an implementation decision under the owner's authorization, not a new permission request prompted by Claude's advisory governance wording.
- **Do not make unsupported conformance claims.** K2 alignment, host trust and restore limitations constrain the release's claims. They do not prevent publishing a clearly bounded semantic package after genuine acceptance and audits. Production credentials, legal validity, external continuity anchors and distributed effects remain external/deferred, with no claim that synthetic tests prove them.

## D2 implementation assignment

The working package name remains **Enterprise Action Requests**, containing two object types (ActionDefinition and ActionRequest) plus native Event profiles. This is a design selection; no model release exists yet.

1. Implement a governed versioned ActionDefinition: identity/version, exact parameter contract, target/precondition, effect boundary, adapter binding, validity/retirement, purpose/authority requirements, compensation pairing, steward/master and optional K2 crosswalk. Add the five exact facets for it; D1's seven-record coverage did not include this new object. Definitions describe actions and never grant permission.
2. Separate descriptive use from the executable fixture. Companies need to describe actions whose real effects belong to external systems. An explicitly descriptive definition can be cataloged and referenced as evidence, but the reference executor must reject it. Only the closed synthetic ordered-label operation can produce an effect in the shipped fixture. No arbitrary command, URL, code or network side effect is accepted. This descriptive/executable distinction is Codex's implementation choice to preserve useful enterprise modeling while keeping the execution claim narrow; frozen audits must review it explicitly.
3. Finalize closed input/record schemas and native projection. Choose one request-ID minting contract that works when the original response is lost; do not mix D1's client-bound ID with an unknown server-minted ID in the same retry digest. Prefer a host-minted request ID outside the client intent bytes, returned through retained key lookup. No second semantic request revision is allowed. Every event issuer is explicit; requested actor/principal are separate.
4. Implement current principal/delegate scope intersection and host-issued evidence in trusted fixture configuration. Policy mutation, definition availability, request admission, cancel, effect, deduplication and receipt share one serialization order. A fresh decision does not change immutable retry identity.
5. Implement lifecycle and history validation, uniform outward disclosure (including errors), tombstones, pending expiry, committed replay, caller observations/corrections, typed compensation and idempotent post-commit native export. Archive validation must not masquerade as authenticated admission or proof of latest history. An export manifest must detect incomplete evidence sets and show export time/sequence.
6. Preserve the two old experiments and their actual counts. Build a new acceptance suite over the final code, including request/definition identity, current rights, ordered bytes, malformed imports, concurrent key/cancel races, rollback/lost response, stale resources, correction history, compensation, descriptive-only execution rejection, export recovery and explicit restore limits. Execute three fresh native Dimensions rather than counting D1's six isolated envelope checks as installations.
7. Select and document one byte algorithm. D1 is a bounded Python canonical contract. JCS requires a real compatible implementation and cross-runtime vectors; adding its name is not enough. Preserve exact ordered arrays, reject duplicate input keys/surrogates and distinguish raw artifact SHA from normative-content digest.
8. Freeze exact code/schema/docs/fixtures, run separate real Claude and Grok implementation audits, fix concrete findings and rerun affected checks. Publish an additive English package with a visible catalog card and Bundles → Layers → Findings → Questions only after those checks. The queue remains EM-XCT-07 researching until the first usable release is actually installed, deployed and verified.
