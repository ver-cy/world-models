role-assertion-reification

Role assertion as a reified n-ary link

Party Role is not a binary property between a party and a host. It is a reified node joining player, host context, role type and validity, so that qualifying facts such as period, extent, evidence and delegation can attach without polluting either endpoint.

    • Name of the permitted binary shorthand property, if any
  2. What is the minimal tuple that makes a Party Role assertion well-formed?definition
    Expected answer
    • Ordered list of mandatory slots (player reference, host reference, role type, valid-from)
    • Well-formedness rule identifier and its failure codes
    • Treatment of an assertion with an unresolvable endpoint
  3. Is there a scoping party distinct from the host that defines or acknowledges the role, and how is it recorded?relationship
    Expected answer
    • Scoping party reference
    • Rule distinguishing scoper from host and from player
    • Cases where scoper and host coincide
  4. Which facts are lost when the assertion is projected to a binary shorthand, and is the projection declared lossy?interoperability
    Expected answer

role-type-and-axes

Role type and classification axes

A role type must declare which axis it expresses. FHIR Provenance separates the functional role with respect to an activity from the structural role indicating competency; contractual and statutory positions form further axes. Collapsing them produces vocabularies that cannot be validated.
