Risk / Control

Provide an embeddable field group that binds one risk assessment context to a referenced risk, links it to referenced controls and their cited effectiveness determinations, and explains the residual position against referenced appetite or tolerance, without owning the risk entity, the control register or any treatment workflow.

rctl-risk-binding-bundleRisk subject binding and assessment framing2 layers

Everything that fixes what was assessed and under which declared frame: the referenced risk and its exact revision, the anchors the assessment is scoped against, the causal chain quantified, the category and taxonomy pins, the scope and horizon, and the criteria, method and expression-mode pins.

rctl-risk-reference-layerReferenced risk, anchors and causal chain3 findings

Reference-carrying fields that attach one assessment context to a pinned risk revision, to the objectives, assets, processes and contextual conditions it is scoped against, and to the risk source, event and consequences it quantifies.

rctl-risk-subject-reference

Referenced risk identity and exact revision pin

Identifies which risk or opportunity entity this assessment context is bound to and which exact revision of its statement was assessed, so an estimate cannot silently drift when the referenced statement is later restated. The referenced entity's own status and lifecycle stay with the owning risk model; only the local binding validity state is held here.

Questions
  1. Which authoritative identifier designates the risk entity that this assessment context is bound to?identity
    Expected answer
    • risk reference identifier value
    • identifier system or namespace
    • assigning authority or system of record
  2. Which exact revision or version of the referenced risk statement was assessed?provenance
    Expected answer
    • risk revision or version token
    • time the revision was retrieved
    • content digest of the assessed statement
  3. How is this assessment context marked once the pinned risk revision is superseded upstream?state
    Expected answer
    • binding validity state code
    • time supersession was detected
    • re-assessment required indicator
  4. Does the bound subject represent a threat, an opportunity, or both, and where is that reading declared?classification
    Expected answer
    • effect polarity code
    • reference to the statement establishing polarity
rctl-risk-context-anchors

Objective, asset, process and context anchors

Records what the risk is assessed against - objectives, assets, processes, organizational units, fixed contextual conditions and applicable jurisdiction or site - as references, so the estimate is interpretable and comparable only within its declared anchor set. Master data for each anchor belongs to its own registry.

Questions
  1. Which objectives does this assessment measure the effect of uncertainty against?relationship
    Expected answer
    • objective reference set
    • objective owner reference
    • objective version or planning period reference
  2. Which assets, processes or organizational units are inside the assessed exposure?composition
    Expected answer
    • asset or process reference set
    • organizational scope reference
    • explicit exclusion statements
  3. Which contextual conditions were treated as fixed rather than assessed for this estimate?constraint
    Expected answer
    • fixed context condition statements
    • reference to the context description in force
  4. Where anchors are jurisdiction-specific or site-specific, how is the applicable location recorded?spatial
    Expected answer
    • jurisdiction code set
    • site or facility reference
    • basis for jurisdictional applicability
rctl-risk-causal-anchors

Risk source, event and consequence anchors

Carries references to the risk source or threat source, the single event or event class whose likelihood is quantified, and the consequences included in the impact estimate, together with named exclusions. This makes likelihood and impact attach to a stated causal chain rather than to a bare label.

Questions
  1. Which risk source or threat source does this estimate attribute the event to?relationship
    Expected answer
    • risk source or threat source reference
    • source characterization such as adversarial or non-adversarial
    • source catalogue reference
  2. Which single event or event class does the likelihood dimension quantify?definition
    Expected answer
    • event reference or event statement
    • event class boundary description
    • distinction between initiating event and consequential event
  3. Which consequences are inside the impact estimate and which named consequences are excluded?composition
    Expected answer
    • included consequence reference set
    • excluded consequence statements
    • order of consequence such as primary or secondary
  4. Which vulnerability or predisposing condition is assumed present for the event to occur?constraint
    Expected answer
    • vulnerability or weakness reference
    • predisposing condition statement
    • status of that condition at the as-of time
  5. Which external threat or hazard catalogue entry is cited, and under which catalogue version?interoperability
    Expected answer
    • threat or hazard catalogue identifier
    • catalogue system or namespace
    • catalogue version token
rctl-risk-frame-layerClassification, scope and method framing3 findings

Fields that pin the interpretive frame of the estimate: category values against a versioned taxonomy, the assessment boundary and time structure, and the criteria set, method, technique and expression mode under which any recorded value must be read.

rctl-risk-taxonomy-pin

Category assignment with taxonomy and version pin

Pins the category values used to classify the referenced risk within this assessment context, together with the taxonomy scheme identifier and version, because category labels are only comparable inside one pinned scheme and category lists differ materially between frameworks.

Questions
  1. Which taxonomy scheme and version supplies the category values asserted here?classification
    Expected answer
    • taxonomy system identifier
    • taxonomy version token
    • publisher of the taxonomy
  2. Which category values are asserted, and is more than one concurrent categorization permitted?constraint
    Expected answer
    • asserted category value set
    • multiplicity rule
    • primary category designation where one is required
  3. How is a category value mapped when the adopting Dimension and an external framework use different schemes?interoperability
    Expected answer
    • mapping reference or crosswalk identifier
    • mapping fidelity such as exact, broader, narrower or unmapped
    • mapping version
  4. Who is authorized to change a pinned category value after an estimate has been recorded against it?authority
    Expected answer
    • authorized role reference
    • required supersession action
    • record of the prior pinned value
rctl-risk-assessment-scope

Assessment scope, horizon and time structure

Declares what the assessment covers and for how long: the assessment boundary and its exclusions, the time horizon over which likelihood is expressed, the as-of time of the assessed state, the time the estimate was recorded, the validity or review-due time, and the decision the assessment was produced for.

Questions
  1. What is the declared boundary of this assessment and what is explicitly excluded from it?constraint
    Expected answer
    • scope statement
    • exclusion statements
    • reason each exclusion was made
  2. Over what time horizon is the likelihood or frequency dimension expressed?temporal
    Expected answer
    • horizon duration or period
    • horizon start reference
    • whether the horizon is rolling or fixed
  3. What are the as-of time of the assessed state and the time the estimate was recorded, and do they differ?provenance
    Expected answer
    • as-of time of the assessed state
    • time the estimate was recorded
    • explanation where the gap is material
  4. Until when is this assessment treated as current, and what triggers an out-of-date state?state
    Expected answer
    • validity or review-due time
    • triggers that force re-assessment
    • current currency state code
  5. Which decision or reporting purpose was this assessment produced for?decision
    Expected answer
    • stated assessment purpose
    • intended consumer or forum reference
    • limits on reuse for other purposes
rctl-risk-criteria-method-pin

Criteria, method and expression-mode pin

Pins the risk criteria set, the assessment method or technique and their versions, plus the expression mode under which values are recorded, so that a level of risk stays interpretable and so that comparison can be refused when pins differ. The mixin references method definitions and never restates technique semantics.

Questions
  1. Which risk criteria set, at which version, defines the scales and thresholds used here?definition
    Expected answer
    • criteria set reference
    • criteria set version token
    • owning criteria registry
  2. Which assessment technique or method was applied, and where is its normative definition held?provenance
    Expected answer
    • method or technique reference
    • method version
    • locator of the normative technique definition
  3. Is the expression qualitative, ordinal, semi-quantitative, quantitative, probabilistic or scenario-based?classification
    Expected answer
    • expression mode code
    • scale type such as nominal, ordinal, interval or ratio
    • permitted operations for that scale type
  4. What must match before two records assessed under different pins may be compared?validation
    Expected answer
    • required matching pin set
    • tolerated differences
    • action when pins do not match
  5. Who approved the criteria set for use in this assessment context?authority
    Expected answer
    • approving role reference
    • approval time
    • scope of the approval
Artifacts
  • Pinned criteria and method recordA retrievable snapshot or resolvable citation of the criteria set, its scales and thresholds, and the method definition in force for this assessment context, sufficient for a reader to re-read a recorded level of risk long after the live criteria have been revised.
rctl-risk-estimation-bundleEstimation and evidential basis2 layers

The dimension declarations that give likelihood and consequence their meaning, the inherent estimate and its exclusion statement, and the assumptions, information sources, estimation basis and uncertainty qualification that make the estimate falsifiable.

rctl-risk-dimension-layerLikelihood and consequence dimension declarations3 findings

Declares the form, unit and scale of each side of the estimate, admitting ordinal bands, probabilities, frequencies, distributions and multi-dimensional impact without imposing any single matrix.

rctl-risk-likelihood-dimension

Likelihood and frequency expression

Declares how the likelihood side is expressed - ordinal band, probability, frequency per unit time, qualitative descriptor or distribution - with its unit, scale reference, horizon dependency and the operations its scale type forbids.

Questions
  1. In what form is likelihood expressed and against which scale or unit?measurement
    Expected answer
    • likelihood expression mode
    • scale reference or unit
    • band label set where ordinal
  2. Does this record separate likelihood of event occurrence from likelihood of adverse consequence?composition
    Expected answer
    • likelihood of initiation or occurrence
    • likelihood of adverse impact given occurrence
    • whether the two are combined and how
  3. If a range or distribution is used, which parameters, bounds and confidence level are stored?quality
    Expected answer
    • distribution family or range type
    • stored parameters and bounds
    • confidence level associated with the range
  4. Which operations on the likelihood value are prohibited by its scale type?constraint
    Expected answer
    • scale type
    • prohibited operations such as multiplication or averaging of ordinals
    • permitted aggregation operations
rctl-risk-consequence-dimension

Impact and consequence dimensions

Declares the impact side, which may be multi-dimensional across financial, safety, health, fundamental-rights, environmental, operational, reputational and regulatory effects, each with its own scale, and states how or whether dimensions are combined and which parties bear each consequence.

Questions
  1. Which impact dimensions are scored, and on which scale is each one expressed?measurement
    Expected answer
    • impact dimension set
    • per-dimension scale reference
    • per-dimension value
  2. How are multiple impact dimensions combined, or is combination explicitly withheld?constraint
    Expected answer
    • combination rule reference or none
    • dominant-dimension rule where used
    • statement that no combined value is asserted
  3. Are safety, health, environmental or fundamental-rights harms represented as first-class dimensions rather than monetized proxies?requirement
    Expected answer
    • non-financial dimension list
    • legal or policy basis requiring the dimension
    • monetization statement where a proxy is used
  4. Which affected parties bear each recorded consequence?relationship
    Expected answer
    • affected party reference per dimension
    • whether the party is internal or external
    • vulnerable-group indicator where applicable
  5. How are secondary or downstream consequences distinguished from primary consequences?classification
    Expected answer
    • consequence order code
    • basis for treating a loss as secondary
    • whether secondary effects are inside the estimate
rctl-risk-inherent-estimate

Inherent estimate and its exclusion statement

Records the estimate produced before, or excluding, the effect of the referenced controls, together with an explicit statement of what inherent was taken to mean, because the term is not uniformly defined and some authorities do not require it at all. Omission must be recorded with a ground rather than left implicit.

Questions
  1. What definition of inherent or gross risk was used, and which control effects were excluded from it?definition
    Expected answer
    • inherent definition statement
    • controls or control classes excluded
    • whether any controls were assumed present
  2. What is the recorded inherent level, and how does it relate the likelihood and impact dimensions?measurement
    Expected answer
    • inherent estimate value per dimension
    • relation or combination applied
    • scale reference used
  3. Was an inherent estimate produced at all, and if not, on what documented ground was it omitted?exception
    Expected answer
    • inherent estimate state code
    • omission ground statement
    • approving role reference for the omission
  4. What derivation or evidence supports the inherent value?evidence
    Expected answer
    • derivation record reference
    • cited observation or dataset references
    • identity of the analyst or tool that produced it
rctl-risk-basis-layerAssessment basis, assumptions and uncertainty1 findings

The evidential qualification of the estimate: assumptions that must hold, the information sources and their currency, whether the value came from judgement, data or a model, the constraints on the analysis, and how much confidence and precision the result can bear.

rctl-risk-basis-and-uncertainty

Assumptions, data basis and uncertainty qualification

Captures the assumptions, information sources, data currency, estimation basis kind and analysis constraints behind the estimate, together with confidence or data-quality grading, uncertainty representation, unmeasurable aspects and precision caveats. This is what allows a reader to judge whether a value rests on incident history, expert judgement, modelled data or a vendor claim, and how far it may be trusted.

Questions
  1. Which explicit assumptions must hold for this estimate to remain valid?constraint
    Expected answer
    • assumption statements
    • assumption owner or source
    • which assumption is flagged critical
  2. Which information sources and datasets were used, and how current were they at the as-of time?provenance
    Expected answer
    • information source references
    • data currency time per source
    • known gaps in the source coverage
  3. Was the estimate elicited from expert judgement, derived from historical data, or produced by a model run?evidence
    Expected answer
    • estimation basis kind
    • number and qualification of estimators where elicited
    • model or tool identity and version where modelled
  4. What confidence or data-quality grade is attached to this estimate, and on which scale?quality
    Expected answer
    • confidence or data-quality grade
    • confidence scale reference
    • uncertainty representation such as range, interval, distribution or narrative caveat
  5. What precision may downstream consumers infer from the stored notation, and which aspects are effectively unmeasurable?validation
    Expected answer
    • precision caveat statement
    • unmeasurable or weakly evidenced aspects
    • rounding or significant-figure rule
Artifacts
  • Assessment basis statementA retained statement of purpose, scope, assumptions, constraints and information sources for one assessment context, corresponding to the documented content that a risk assessment report is expected to carry alongside its results.
  • Estimate derivation recordA record of the inputs, technique run and intermediate results that produced a recorded estimate, retained so the value can be re-read and challenged without re-running the analysis, and so the origin of a characterization is traceable to a human or automated actor.
rctl-risk-residual-bundleResidual position and comparability2 layers

The post-control estimate with its control linkage and change explanation, the comparison against referenced appetite or tolerance with its governance stamps, and the comparability, aggregation and scenario-dependence controls that stop values from being combined when their pins do not match.

rctl-risk-residual-layerResidual estimate, control linkage and appetite comparison2 findings

Fields that record the post-control estimate, the controls relied on and the effectiveness determinations cited for them, the explanation of change, and the outcome of comparing the residual position against a referenced tolerance statement.

rctl-risk-residual-estimate

Residual estimate, control linkage and change explanation

Records the estimate after the referenced controls are taken into account, the control references relied on, the effectiveness determinations cited for each of them, which dimension changed, and why. Effectiveness is cited by reference and is produced by the control assessment model; this finding never derives, revises or re-opens it.

Questions
  1. Which controls were relied on when producing the residual estimate, and by which reference?relationship
    Expected answer
    • relied-on control reference set
    • control implementation statement reference
    • scope of reliance placed on each control
  2. Which effectiveness determination is cited for each relied-on control, and who produced it?evidence
    Expected answer
    • effectiveness determination reference
    • determination outcome as recorded by its owner
    • producing role and determination time
  3. Which dimension changed between the inherent and residual estimates - likelihood, consequence, or both?composition
    Expected answer
    • changed dimension set
    • per-dimension before and after values
    • narrative explanation of the change
  4. How is the residual value marked as an adjusted rather than an initial characterization?state
    Expected answer
    • characterization state code
    • reference to the initial characterization
    • time the adjustment was recorded
  5. What is recorded when a control is referenced but no effectiveness determination exists for it?exception
    Expected answer
    • reliance-without-determination flag
    • assumed effectiveness statement
    • effect on the confidence grade
rctl-risk-appetite-comparison

Appetite or tolerance reference and comparison outcome

References the appetite or tolerance statement in force, records the outcome of comparing the residual estimate against it, and stamps who recorded the comparison and which acceptance or authorization decision, if any, was taken elsewhere. Setting, approving and enforcing appetite are not performed here.

Questions
  1. Which appetite or tolerance statement, at which version, was the residual estimate compared against?relationship
    Expected answer
    • appetite or tolerance statement reference
    • statement version token
    • threshold references applied
  2. What is the recorded comparison outcome and on which scale is it expressed?measurement
    Expected answer
    • comparison outcome code
    • distance to threshold where the scale supports it
    • scale reference used for the comparison
  3. Who recorded the comparison, and which decision record shows the residual position being accepted?ownership
    Expected answer
    • role reference that recorded the comparison
    • acceptance or authorization decision reference
    • time each stamp was recorded
  4. What is recorded when no applicable tolerance statement exists for the pinned criteria?exception
    Expected answer
    • no-applicable-tolerance flag
    • escalation route reference
    • effect on the comparison outcome
  5. Which downstream consumers may read the comparison outcome without access to the underlying estimates?access
    Expected answer
    • consumer role set
    • fields released with the outcome
    • caveats that must accompany the release
rctl-risk-comparability-layerComparability, aggregation and scenario dependence1 findings

The gate that decides whether two assessment contexts may be compared, rolled up or reported together, the caveats any permitted aggregate must carry, and how one risk assessed under several scenarios is represented without collapsing into a single false value.

rctl-risk-comparability-limits

Comparability verdicts, aggregation caveats and scenario dependence

Records whether records may be placed on a common scale, which pins failed to match when they may not, which caveats must travel with any permitted aggregate, and how scenario variants and a designated reference case are represented. The model refuses to define a normalization algorithm it has no authority to assert.

Questions
  1. Under what conditions may two assessment contexts be placed on the same scale?validation
    Expected answer
    • required matching pin set
    • comparability verdict code
    • named mismatched pins where the verdict is negative
  2. Which caveats must travel with any aggregate produced from these records?constraint
    Expected answer
    • aggregation caveat statements
    • permitted aggregation operations for the scale type
    • prohibition on stripping caveats downstream
  3. How is scenario dependence recorded when one risk is assessed under several scenarios?composition
    Expected answer
    • scenario identifier set
    • per-scenario estimate references
    • scenario definition reference and version
  4. Which scenario or variant is designated the reference case for reporting, and by which role?decision
    Expected answer
    • reference case flag
    • designating role reference
    • basis for the designation
  5. How are records assessed under a superseded criteria version handled in a current roll-up?lifecycle
    Expected answer
    • superseded-criteria handling code
    • migration or restatement reference
    • exclusion from the aggregate where no migration exists
