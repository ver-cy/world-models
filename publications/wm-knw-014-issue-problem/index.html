Issue / Problem

Give an agent the format-neutral context needed to recognize, record, classify, analyse, relate, govern and hand off a recognized discrepancy between an observed state and a required or expected state, without owning the work, change, enforcement or audit trail that resolves it.

issue-definition-and-identityDiscrepancy definition, identity and classification2 layers

Establishes what the record asserts, how it is uniquely and stably identified across systems and duplicates, and how it is typed and graded.

discrepancy-definitionDiscrepancy assertion and record identity2 findings

The propositional content of the issue — observed versus expected against a named norm — and the identity apparatus that keeps the record addressable and de-duplicated.

discrepancy-statement

Observed state, expected state and reference norm

The atomic assertion that makes something an issue: what was observed, what was required or expected, which authored norm or requirement establishes the expectation, and the version of that norm in force when the divergence was recognized.

Questions
  1. What observed state or behaviour is asserted, and in what terms is it expressed?definition
    Expected answer
    • Observed-state description in controlled prose
    • Measured or captured values with units where the divergence is quantitative
  2. What expected or required state is the observation being compared against?requirement
    Expected answer
    • Expected-state description
    • Acceptance threshold or tolerance where applicable
  3. Which authored requirement, specification or norm clause establishes that expectation, and which version of it was in force at recognition?provenance
    Expected answer
    • Resolvable reference to the norm or requirement clause
    • Norm version or edition identifier in force at recognition
  4. Is the divergence asserted as a categorical failure to conform or as a quantified deviation?classification
    Expected answer
    • Divergence mode code (categorical or quantified)
    • Deviation magnitude and direction when quantified
issue-record-identity

Issue identity, correlation and duplicate resolution

How the issue record is named, which identifier is authoritative, how correlation across runs and systems is achieved without conflating identity, and how duplicates are detected, merged and superseded.

Questions
  1. Which system of record issues the authoritative identifier for this issue, and what is that identifier?identity
    Expected answer
    • Master-system identifier value
    • Identifier-issuing system reference and namespace
  2. What stable correlation value lets the same discrepancy be recognized across repeated detections or tool runs?identity
    Expected answer
    • Correlation identifier or fingerprint value
    • Fingerprint algorithm name and version
  3. On what criteria is another record judged a duplicate rather than a related or recurring issue?constraint
    Expected answer
    • Duplicate-decision criteria set
    • Comparison fields and matching tolerance
  4. When records are merged, which record survives as canonical and how is the derivation of the retired record preserved?provenance
    Expected answer
    • Canonical record reference
    • Derivation link from retired to canonical record and merge justification
issue-classificationTypology and grading2 findings

Assignment of issue type and category codes from governed schemes, and of severity, priority, urgency and impact grades that drive routing and authority.

issue-typology

Issue type and category coding

The kind of discrepancy (defect, nonconformance, service problem, occurrence, enhancement gap, process deviation) and its category codes bound to externally governed classification schemes.

Questions
  1. What kind of discrepancy is this, and does the chosen kind change which lifecycle or authority applies?classification
    Expected answer
    • Issue type code
    • Lifecycle or authority profile implied by the type
  2. Which external classification scheme supplies the category codes, and at which scheme version were they assigned?interoperability
    Expected answer
    • Classification scheme identifier and version
    • Assigned category code values
  3. May an issue carry codes from more than one scheme simultaneously, and how are conflicting codes reconciled?constraint
    Expected answer
    • Multi-scheme cardinality rule
    • Conflict-reconciliation precedence rule
  4. What evidence justifies reclassifying an issue after registration, and is the prior classification retained?decision
    Expected answer
    • Reclassification justification text and authority reference
    • Superseded classification values with their validity interval
severity-priority-and-impact-grading

Severity, priority, urgency and assessed impact

Independent grading axes: intrinsic seriousness of the discrepancy, the handling order assigned to it, and the assessed consequence, including the risk classification that determines which authority must review it.

Questions
  1. Which grading axes are carried separately, and what is the permitted value set of each?measurement
    Expected answer
    • Severity value set and definitions
    • Priority and urgency value sets and definitions
  2. Which grade threshold escalates the issue to a higher review authority or to an external body?authority
    Expected answer
    • Threshold value that triggers escalation
    • Competent authority or board designated at that threshold
  3. Must an assigned risk or severity classification be reviewed and endorsed by a party other than the assigner?validation
    Expected answer
    • Endorsement requirement flag and endorsing party reference
    • Endorsement decision timestamp
  4. On what stated basis was the grade derived, so that a later reader can challenge it?evidence
    Expected answer
    • Grading rationale text
    • Grading scheme identifier and version applied
recognition-evidence-and-provenanceRecognition context, evidence and provenance2 layers

How, when, where and by whom the discrepancy came to be known, what evidence supports it, and how confident and attributable each assertion is.

recognition-contextDetection, time and situation3 findings

The circumstances of recognition: origin and channel, the separate time anchors that must not be collapsed, and the environment and configuration in which the divergence appeared.

detection-and-report-origin

Detector, reporting channel and obligation basis

Who or what recognized the discrepancy, through which intake channel it entered, and whether the report was made under a mandatory obligation or voluntarily.

Questions
  1. Who or what detected the discrepancy — a person, an automated tool, an audit, a customer complaint or a monitoring service?provenance
    Expected answer
    • Detector reference with agent type
    • Tool component name and version where automated
  2. Was the report submitted under a mandatory reporting obligation or voluntarily, and which rule creates the obligation?authority
    Expected answer
    • Reporting basis code (mandatory or voluntary)
    • Reference to the obligating rule or clause
  3. Through which intake channel did the report arrive, and what minimum data set did that channel require?process
    Expected answer
    • Intake channel identifier
    • Minimum required field set for that channel
  4. Which quality-data source category does the origin fall into for periodic source analysis?classification
    Expected answer
    • Source category code such as complaint, audit, service record, returned product or process monitoring
    • Source system reference
Artifacts
  • Intake report submissionThe as-submitted report that caused the issue to be registered — an occurrence report satisfying a mandated minimum data set, a complaint, an audit finding sheet or a machine-generated analysis run output. Retained unaltered so that later edits to the issue record can be distinguished from what was originally asserted.
temporal-anchors

Separated time anchors and reporting deadlines

The distinct instants that must be recorded independently — when the divergence occurred or began, when it was detected, when it was reported, when the record was ingested, and when onward transmission was due — together with their timezone discipline.

Questions
  1. Which distinct time anchors are recorded, and which of them are unknown rather than absent?temporal
    Expected answer
    • Occurrence, detection, report and ingestion timestamps
    • Explicit unknown markers distinguishing unknown from not-applicable
  2. Is the divergence a point event or an interval, and if an interval, what bounds its start and end?temporal
    Expected answer
    • Interval start and end timestamps
    • Boundedness qualifier for open-ended intervals
  3. What externally imposed deadline applies to reporting or onward transmission of this record, and against which anchor is it measured?constraint
    Expected answer
    • Deadline duration and the anchor it is measured from
    • Deadline satisfaction status and actual elapsed duration
  4. How is a timestamp represented when the instant is known in UTC but the local offset is not?interoperability
    Expected answer
    • Representation rule for unknown local offset
    • Recorded local civil time and location where the offset matters analytically
situational-and-configuration-context

Location, environment and configuration at recognition

Questions
  1. At what physical, organizational or logical location was the divergence observed?spatial
    Expected answer
    • Location reference with the location scheme used
    • Coordinates or facility/site identifier where the discrepancy is physically situated
  2. What configuration, build, batch or serial state of the affected subject was in force when the divergence appeared?state
    Expected answer
    • Configuration or version identifier of the affected subject
    • Batch, lot or serial number for physical items
  3. What operating or process conditions were present that a reproduction attempt would need to recreate?composition
    Expected answer
    • Named environment or process-condition set
    • Parameter values distinguishing this environment from others
evidence-and-provenanceEvidence, reproducibility and provenance2 findings

The supporting material for the assertion, whether the divergence can be reproduced or re-observed, and the attribution, derivation and confidence of every claim carried.

evidence-set-and-reproducibility

Evidence set, sufficiency and reproduction

Which evidence items support the discrepancy assertion, whether they are sufficient for the disposition sought, and whether and how the divergence can be reproduced or re-observed on demand.

Questions
  1. What evidence items are relied on, and where does each authoritatively reside?evidence
    Expected answer
    • Evidence item references with type and custodian
    • Resolvable location or repository identifier for each item
  2. Is the evidence sufficient for the disposition sought, and if not, what is missing?quality
    Expected answer
    • Sufficiency assessment with assessing party reference
    • Enumerated evidence gaps blocking the sought disposition
  3. Can the divergence be reproduced or re-observed, and under what stated preconditions?validation
    Expected answer
    • Reproducibility status code
    • Preconditions and steps required for reproduction, with observed reproduction rate
  4. How is each evidence item shown to be unaltered since capture?security
    Expected answer
    • Content digest with algorithm identifier
    • Capture timestamp and capturing agent reference
Artifacts
  • Evidence itemA captured item relied on to support the discrepancy assertion: log extract, measurement record, image, physical sample reference, tool output fragment or witness statement. Each is referenced with a content digest so that alteration after capture is detectable.
  • Reproduction procedureThe stated preconditions, steps and expected divergent outcome that allow an independent party to re-observe the discrepancy, together with the observed reproduction rate.
provenance-attribution-and-confidence

Attribution, derivation and confidence of assertions

For each substantive claim on the record — the observation, the classification, the causal conclusion — who asserted it, from what it was derived, and how confident or contested it is.

Questions
  1. Which agent asserted each substantive claim on the record, and in what capacity?provenance
    Expected answer
    • Agent reference per claim with role at time of assertion
    • Assertion timestamp
  2. From which prior record, report or analysis was this claim derived?relationship
    Expected answer
    • Derivation references to source records or analyses
    • Derivation type such as transcription, aggregation, merge or restatement
  3. What confidence is attached to the assertion, and on what scale is it expressed?measurement
    Expected answer
    • Confidence value and the scale or rank definition used
    • Basis for the confidence assignment
  4. Is any claim contested, and how is the competing position recorded without overwriting the original?exception
    Expected answer
    • Dispute marker with disputing party reference
    • Competing assertion retained alongside the original with its own attribution
impact-and-causal-analysisImpact, recurrence and causal analysis2 layers

What the discrepancy affects and how widely, how repeated observations aggregate onto one record, and what the investigation concluded about cause and available mitigation knowledge.

impact-and-extentImpact extent and occurrence aggregation2 findings

The affected population and consequence of the divergence, and the rules by which multiple observations are counted as one issue or as several.

affected-subjects-and-extent

Affected subjects, consequence and extent of spread

Which subjects are affected, what consequence is assessed, and how far the divergence is believed to have spread across items, services, populations or time.

Questions
  1. Which subjects — items, services, processes, data sets or populations — are affected, and which are only suspected?composition
    Expected answer
    • Affected subject references with confirmed or suspected qualifier
    • Subject type per reference
  2. What consequence is assessed, and is it actual, potential or both?measurement
    Expected answer
    • Consequence description with modality qualifier
    • Quantified consequence measures such as affected count, downtime or loss where available
  3. Could the same divergence extend to items already delivered, in process or not yet examined?constraint
    Expected answer
    • Extent-of-spread assessment across delivered, in-process and unexamined populations
    • Bounding rationale limiting the affected population
  4. Is any affected subject designated critical, and does that designation change the required review path?authority
    Expected answer
    • Criticality designation per affected subject
    • Review path implied by the designation

    Expected answer
    • Aggregation rule statement

  2. How many times has the condition been observed, and over what interval?measurement
    Expected answer

  3. Relative to a previous assessment baseline, is this condition new, unchanged, updated, absent, renamed or moved?state

causal-hypothesis-and-root-cause

Hypothesis, proximate cause, root cause and contributing factors

The investigation outcome recorded on the issue: candidate hypotheses, the immediate cause of the divergence, the underlying cause whose removal prevents recurrence, and contributing factors, each with its evidential basis and status.

Questions
  1. What candidate causes were considered, and on what evidence was each accepted or eliminated?evidence
    Expected answer
    • Candidate cause statements with status
    • Eliminating or confirming evidence reference per candidate
  2. Which cause is asserted as immediate and which as underlying, and are contributing factors distinguished from both?classification
    Expected answer
    • Proximate cause statement
    • Root cause statement and contributing factor statements, each separately typed
  3. Which analysis method produced the conclusion, and who performed it?process
    Expected answer
    • Analysis method name and version
    • Analyst or investigating body reference and completion timestamp
  4. Is the causal conclusion provisional or confirmed, and what would be needed to confirm it?quality
    Expected answer
    • Causal conclusion status code
    • Outstanding confirmation conditions
  5. If no cause could be determined, how is that outcome recorded so it is not mistaken for an unfinished investigation?exception
    Expected answer
    • Undetermined-cause outcome code with justification
    • Conditions under which the investigation would be reopened
Artifacts
  • Causal analysis reportThe structured record of the investigation supporting the causal conclusion — the method applied, data examined, hypotheses eliminated and the reasoning that reaches the stated cause. Required wherever the governing rule obliges the cause of a nonconformity to be investigated and the investigation documented.
known-error-and-workaround-knowledge

Known-error designation and workaround knowledge

The knowledge state reached when a cause is documented and a means of avoiding or reducing the impact exists, expressed as reusable knowledge rather than as executed work.

Questions
  1. On what conditions is the issue designated a known error, and what must be documented before that designation holds?definition
    Expected answer
    • Known-error designation criteria
    • Required documented elements, minimally a cause and a means of avoidance
  2. What documented means exists to avoid or reduce the impact without removing the cause, and what are its limits and side effects?requirement
    Expected answer
    • Workaround description with applicability conditions
    • Stated limitations, residual impact and side effects
  3. Under which configurations, versions or populations is the documented workaround valid, and when does it expire?constraint
    Expected answer
    • Applicability scope by configuration, version or population
    • Validity end condition or review date
  4. When a permanent removal of the cause is achieved, how is the known-error knowledge retired without losing its history?lifecycle
    Expected answer
    • Retirement status of the known-error entry
    • Reference to what supersedes it and the retirement justification
Artifacts
  • Known-error knowledge entryThe reusable knowledge record stating the documented cause, current status of a permanent removal, and the conditions under which the entry applies. Distinct from the issue record because it is consumed by parties handling unrelated incidents who never touch the issue itself.
  • Workaround instructionThe stated means of avoiding or reducing impact while the cause remains present, with preconditions, steps, applicability scope and residual risk. Held as instruction content; performing it is work owned by the action model.
